# Students-Affairs-
Student Affairs Service Management System
A web-based system designed to make student affairs services easier to
access and manage. Students can view available services, submit service
requests, upload required documents, and follow the status of their
requests. Student affairs employees can review requests and update their
status, while administrators manage users and services.
Project type: Software Engineering
Platform: Web Application
Project stage: Requirements analysis and system design

Project Overview
Students often need to visit the student affairs office or contact staff
to ask about services and follow up on requests. This can take time and
make it difficult to know the current status of a request.

The proposed system provides one online place for students to access
services and track their requests. It also helps student affairs
employees organize and process requests more efficiently.
Main Objectives
- Make student affairs services easier to access.
- Allow students to submit requests online.
- Enable students to track request status and view request history.
- Help employees review requests and update their status.
- Give administrators tools to manage users and available services.
- Support better organization and handling of uploaded documents.
Main Features
Student
- Log in to the system.
- View available student affairs services.
- Submit a service request.
- Upload the required documents.
- Track the status of a request.
- View previous requests and their history.
- Receive notifications about request updates.
Student Affairs Employee
- View submitted requests.
- Review request details and uploaded documents.
- Update request status.
- Add a comment when a request is rejected, where applicable.
Administrator
- Manage user accounts.
- Manage available services.
- Maintain the information used by the system.
System Actors
- Student: Uses services and submits and tracks requests.
- Student Affairs Employee: Reviews and processes requests.
- Administrator: Manages users and services.
Requirements
The proposed system includes functional requirements such as
authentication, service browsing, request submission, request tracking,
request management, notifications, request history, and user/service
management.

It also considers non-functional requirements, including security,
performance, usability, reliability, compatibility, maintainability,
data integrity, and privacy.
System Design
The project design includes:
- Use Case Diagram: Shows the system actors and the actions they
  can perform.
- Use Case Descriptions: Describe workflows such as submitting a
  service request and updating its status.
- Class Diagram: Describes the main system classes and their
  relationships.
- ER Diagram / Database Design: Describes the data entities and
  relationships needed to store users, services, requests, documents,
  status updates, and notifications.
Main Database Entities
The proposed database includes the following tables:
- faculty
- users
- students
- employees
- admins
- services
- required_documents
- requests
- uploaded_documents
- status_updates
- notifications
The design uses primary keys, foreign keys, and constraints to support
data integrity and relationships between records.
